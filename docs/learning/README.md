# 학습 아카이브

프로젝트를 진행하면서 면접, 포트폴리오, 회고에 다시 활용할 수 있는 학습 내용을 저장한다.

이 아카이브는 구현 명세나 전역 설계의 원본이 아니다. 원본 결정은 `docs/`, `specs/`, ADR에 남기고, 여기에는 그 결정을 이해하기 쉬운 학습 노트로 정리한다.

## 분류

- [architecture/](./architecture/): 모듈 경계, 결합도, DI, adapter/repository 패턴
- [testing/](./testing/): TDD, mock 전략, 테스트 계약, 검증 기준
- [data-modeling/](./data-modeling/): Prisma 모델, 기간 키, JSON 필드, 스냅샷 설계
- [operations/](./operations/): 멱등성, 재시도, 로그, 관측성, 운영 제약
- [external-api/](./external-api/): Amplitude, Sentry, 외부 API 한도와 실패 처리

## 노트 작성 기준

각 노트는 아래 흐름을 따른다.

```text
문제 -> 핵심 개념 -> 이 프로젝트의 예시 -> 대안 -> 선택 이유 -> 면접 설명 문장
```

구조가 있는 설계 내용은 가능한 한 ASCII 구조도를 포함한다. 복잡한 그림보다 나중에 빠르게 다시 읽고 설명할 수 있는 단순한 흐름도를 우선한다.

## 기록 워크플로

학습 노트는 모든 설명을 자동으로 저장하지 않는다. 다음 흐름을 따른다.

```text
후보 감지 -> 사용자 확인 -> 기존 노트 검색 -> 기존 노트 개선 또는 새 노트 생성
```

기록 후보는 아래 기준 중 하나를 만족하는 내용이다.

- 중요한 설계 결정이나 트레이드오프를 설명한다.
- 테스트 전략, mock 전략, 검증 기준을 이해하는 데 도움이 된다.
- 데이터 모델링, 운영 정책, 외부 API 실패 처리처럼 면접에서 설명할 가치가 있다.
- 현재 기능을 넘어 이후 Phase에서도 다시 참조할 가능성이 높다.

중복 주제는 새 파일을 만들지 않고 기존 노트를 개선한다. 기존 노트에는 새 예시, 구조도, 대안, 관련 작업 링크를 추가한다.
